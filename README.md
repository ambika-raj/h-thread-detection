# H-Thread Detection

### Context-Aware and Explainable Container Runtime Security Monitoring

## 1. Project Overview

H-Thread Detection is a proposed container runtime security monitoring system designed to monitor selected activities inside running Docker containers and convert suspicious runtime events into understandable, context-aware security alerts.

The project aims to make runtime security events easier to interpret by providing relevant container and process information, severity classification, supporting evidence, and investigation recommendations.

## 2. Problem Statement

Containerised applications are widely used in modern cloud environments. However, suspicious runtime activities such as unexpected process execution, sensitive file access, unusual network behaviour, and privilege-related operations can introduce security risks.

Runtime monitoring tools can generate security events, but interpreting these events and understanding their context may require additional investigation.

H-Thread Detection aims to develop an additional processing and visualisation layer that helps users understand selected runtime security events and investigate them more effectively.

## 3. Project Objectives

- Monitor selected runtime activities in Docker containers.
- Explore eBPF-based runtime monitoring through Falco.
- Process and analyse security events using a Python backend.
- Enrich events with container and process context.
- Apply transparent, context-aware severity classification.
- Generate understandable alerts and investigation recommendations.
- Store and retrieve security events and alerts.
- Display monitoring information through a web dashboard.

## 6. Planned Core Features

1. **Runtime Event Monitoring:** Receive selected security events generated by Falco.
2. **Event Processing:** Parse and organise the incoming event data.
3. **Context Enrichment:** Associate events with relevant container and process information.
4. **Severity Classification:** Assign application-level severity based on documented rules and context.
5. **Explainable Alerts:** Display why an event was flagged and what evidence supports it.
6. **Alert History:** Store and retrieve past events and alerts.
7. **Dashboard:** Visualise container information, event history and security alerts.
8. **Investigation Recommendations:** Suggest possible actions for human review rather than automatically terminating containers or processes.

## 7. Research Direction

The research component will investigate whether a context-enrichment and explainable alert-processing layer can improve the interpretability and investigation usefulness of runtime security events generated by Falco, compared with presenting raw Falco alerts.

The research will include a literature review, system methodology, controlled runtime scenarios and evaluation of the proposed approach.
